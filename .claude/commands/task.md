Взять задачу в работу.

1. Посмотри список задач: `ls Tasks/`
2. Если задача указана явно (`/task TASK-001`) — бери её
3. Если не указана — бери задачу с наименьшим номером
4. Прочитай файл задачи полностью
5. Перед началом выведи план:
   ```
   Задача: [номер] [название]
   План:
   1. ...
   2. ...
   3. ...
   Критерии готовности: ...
   ```
6. Выполни задачу по шагам
7. После каждого значимого шага — запусти тесты
8. По завершении — перемести: `mkdir -p Tasks/done && mv Tasks/TASK-NNN*.md Tasks/done/`

## Правила

- Следуй паттернам из существующего кода (Router → Service → Repository → Model)
- Проверяй что существующие тесты не сломались
- Коммить после завершения задачи
- Если задача содержит "Критерии готовности" — проверь каждый пункт

## Формат коммита

```
[component] Краткое описание на русском

- Что сделано
- Какие файлы затронуты
```

Префиксы: `[backend]`, `[frontend]`, `[docker]`, `[infra]`, `[docs]`, `[test]`, `[fix]`, `[refactor]`

Если задача непонятна — не додумывай, спроси.
