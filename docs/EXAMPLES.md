# Примеры использования ErrorLens

## Сценарий 1: Отладка TypeError в React-приложении

### Ситуация
При клике на кнопку "Профиль" страница ломается.

### Действия
1. Открываем страницу с проблемой
2. Кликаем на букмарклет ErrorLens — появляется виджет записи
3. Кликаем на кнопку "Профиль" — воспроизводим баг
4. Нажимаем "Остановить и отправить"

### Пример ответа ErrorLens

```json
{
  "summary": "Ошибка доступа к свойству несуществующего объекта",
  "probable_cause": "Переменная user равна null или undefined при обращении к user.profile.name",
  "suggested_fix": "Добавить проверку: if (user?.profile?.name) { ... } или использовать optional chaining",
  "severity": "medium",
  "details": "TypeError: Cannot read property 'name' of undefined в ProfilePage.jsx:42"
}
```

## Сценарий 2: Сетевая ошибка 500 при отправке формы

### Ситуация
Форма регистрации показывает "Ошибка сервера" без подробностей.

### Действия
1. Открываем страницу регистрации
2. Активируем ErrorLens
3. Заполняем форму и отправляем
4. Останавливаем запись

### Пример ответа ErrorLens

```json
{
  "summary": "Сервер вернул внутреннюю ошибку при регистрации",
  "probable_cause": "Сбой на бэкенде при обработке POST /api/users — возможно, проблема с валидацией email или дубликат пользователя",
  "suggested_fix": "Проверить серверные логи на ошибки валидации. Убедиться, что email уникален. Проверить подключение к БД.",
  "severity": "high",
  "details": "POST /api/users → 500 Internal Server Error. Тело ответа: {\"error\": \"duplicate key value violates unique constraint\"}"
}
```

## Сценарий 3: CORS ошибка при интеграции

### Ситуация
Фронтенд не может получить данные от API.

### Действия
1. Открываем страницу, которая загружает данные
2. Запускаем запись
3. Наблюдаем ошибку в консоли
4. Получаем анализ

### Пример ответа ErrorLens

```json
{
  "summary": "Блокировка запроса из-за политики CORS",
  "probable_cause": "Сервер api.example.com не отправляет заголовок Access-Control-Allow-Origin для домена вашего фронтенда",
  "suggested_fix": "Настроить CORS на бэкенде: добавить заголовок Access-Control-Allow-Origin с доменом фронтенда или '*' для разработки",
  "severity": "high",
  "details": "Access to fetch at 'https://api.example.com/data' from origin 'http://localhost:3000' has been blocked by CORS policy"
}
```

## Сценарий 4: Память и производительность

### Ситуация
Страница тормозит после длительного использования.

### Действия
1. Активируем ErrorLens на проблемной странице
2. Выполняем типичные действия пользователя
3. Ждём появления проблем
4. Останавливаем запись

### Пример ответа ErrorLens

```json
{
  "summary": "Множественные предупреждения о производительности",
  "probable_cause": "Event listener добавляется при каждом рендере компонента без очистки. За 5 минут накопилось 847 слушателей на событие scroll.",
  "suggested_fix": "Добавить cleanup в useEffect: return () => window.removeEventListener('scroll', handler). Использовать debounce для scroll-обработчика.",
  "severity": "medium",
  "details": "Консоль: [Violation] Added non-passive event listener (x847)"
}
```

## Сценарий 5: 404 ошибки ресурсов

### Ситуация
Иконки и изображения не загружаются на продакшене.

### Действия
1. Открываем страницу с отсутствующими изображениями
2. Записываем с ErrorLens
3. Получаем список всех 404 ошибок

### Пример ответа ErrorLens

```json
{
  "summary": "Множественные 404 ошибки для статических ресурсов",
  "probable_cause": "Пути к изображениям указаны относительно, но после деплоя структура папок изменилась. Ресурсы ищутся по путям /assets/icons/*.svg, но реально находятся в /static/assets/",
  "suggested_fix": "Использовать абсолютные пути от корня: /static/assets/icons/. Или настроить publicPath в webpack/vite конфиге.",
  "severity": "low",
  "details": "GET /assets/icons/user.svg → 404\nGET /assets/icons/settings.svg → 404\nGET /assets/images/logo.png → 404"
}
```

## Экспорт для Jira/GitHub

После анализа нажмите "Экспорт MD" для скачивания результата в формате Markdown:

```markdown
## Анализ ошибки ErrorLens

**Критичность:** HIGH

### Итог
Сервер вернул внутреннюю ошибку при регистрации

### Вероятная причина
Сбой на бэкенде при обработке POST /api/users

### Рекомендация
Проверить серверные логи на ошибки валидации

### Детали
POST /api/users → 500 Internal Server Error

---
*Сгенерировано ErrorLens*
```

Этот формат легко вставить в описание тикета Jira или GitHub Issue.
